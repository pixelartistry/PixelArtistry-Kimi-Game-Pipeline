ComfyUI: nodes, models and workflows

Everything the four workflows in this repo need, read from every node in the workflow files. Tested on ComfyUI 0.39.2 (ComfyUI-Easy-Install, Python 3.12, PyTorch 2.8 + CUDA 12.8) on an RTX 5080.

Shortcut: the two 3D workflows are Kimi's versions of my 05p prop workflow. My Animated-Characters installer installs every node pack and model they need, at the tested versions. Run it first, then add the Qwen models below.

The workflows

In the workflows folder. Copy them into ComfyUI\user\default\workflows\Kimi\, so they show up in the workflow sidebar.

FileStepWhat it does
Kimi_Concept_QwenImage21_API.jsonConcept imagesQwen Image 2.1 text-to-image, 1024 × 1024. Saved in API format (the way Kimi submits jobs); drag it into ComfyUI to open it.
Kimi_T3e_Rowan_QwenEdit2511.jsonHero T-poseQwen Image Edit 2511 with the 4-step Lightning LoRA: turns the approved hero concept into a T-pose without changing the character.
Kimi_LowPoly_GameAsset.jsonImage to 3D (Pixal3D)Concept image → Pixal3D → watertight → low-poly (4k triangles) → normal-map bake → UltraTex textures → one GLB.
Kimi_LowPoly_GameAsset_TRELLIS2.jsonImage to 3D (TRELLIS.2)The same chain with TRELLIS.2 geometry, the fast sampling profile, 1024 resolution and a 6k triangle budget. I used this one for most props and the hero.

In both 3D workflows, paste your Blender path into the Blender path node (forward slashes, e.g. D:/Blender/blender.exe) and load your image in Load Image. Use square 1024 × 1024 input images.

What Kimi changed in my workflow

Kimi started from PixelArtistry_05p_Image_to_LowPoly_Prop_UltraTex, ran it unchanged as a baseline, then tested one change at a time. The result was about 19% faster on the fence (517 s → 421 s), with the same quality and one clean piece.

SettingMy original (05p)Kimi_LowPoly_GameAssetWhy
LODTailor high-poly cap (step 4)6,000,000 tris50,000 trisA game prop doesn't need millions of faces before it's reduced to a few thousand.
WTiVo final_res15361024Less detail that would be thrown away later anyway.
Final low-poly target2,000 tris (2k)4,000 tris (4k)Thin parts like fence beams collapse at 2k.
UltraTex textures20482048 (unchanged)

The TRELLIS.2 version adds: TRELLIS.2 instead of Pixal3D, the fast sampling profile (12 structure / 12 shape / 8 upsample steps), upsample, Quad Reconstruct and WTiVo all at 1024, and a 6,000-triangle final budget. The 1024 setting matters: at 1536, TRELLIS.2 got stuck on the cottage for over an hour.

The note nodes inside these two workflows still include a "settings by VRAM" table from my original pack, with a 6 GB row. My own measurements for this project were higher; see the hardware note.

Licences that matter

  • Qwen Image 2.1 is under the Qwen Research License Agreement: the model itself is for non-commercial research and evaluation; commercial use of the model needs a separate licence from Alibaba. The images you generate are different: Qwen has said on X that outputs aren't part of the licensed materials, so you can use them commercially. The licence text doesn't spell that out yet, so check the current terms before you sell a game.
  • FLUX.2 [klein] base 9B, which UltraTex uses for the textures, is under the FLUX Non-Commercial License by Black Forest Labs. The licence says you may use outputs "for any purpose (including for commercial purposes)", except to train a model that competes with FLUX. So the textures you make are yours to use.
  • UltraTex weights: ModelScope lists them as MIT, but they are adapters for the FLUX.2 model above, so its licence applies too.
  • DINOv3 (used by Pixal3D and TRELLIS.2 conditioning) has its own licence from Meta.
  • Qwen Image Edit 2511, TRELLIS.2, Pixal3D, MoGe and BiRefNet are Apache-2.0 or MIT.
  • MostAadTech's node packs are mostly GPL-3.0. That matters if you redistribute the nodes, not for the meshes you make with them.

This is a summary, not legal advice. Read each licence yourself before commercial use.
