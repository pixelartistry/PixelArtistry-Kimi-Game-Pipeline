Set up Kimi Code and the three MCP servers

Windows 10 or 11. At the end, Kimi K3.1 Pro can drive ComfyUI, Blender and Godot from one terminal.

1 · What to install first

  • Git for Windows: the Kimi Code CLI needs it on Windows.
  • Node.js LTS (22 or newer): runs the ComfyUI and Godot MCP servers through npx.
  • ComfyUI-Easy-Install (or any recent ComfyUI) with the nodes and models from the ComfyUI page. New to ComfyUI? Follow my TRELLIS.2 Installation Guide first: it sets up ComfyUI-Easy-Install and TRELLIS.2 step by step.
  • Blender (I used 5.1 for the live cleanup).
  • Godot 4.x for Windows (I used 4.7). Unzip it anywhere; the zip contains a normal exe and a _console.exe.

2 · Kimi Code CLI

Install

In PowerShell (from the official getting-started guide):

irm https://code.kimi.com/kimi-code/install.ps1 | iex

Or with npm (Node.js 22.19 or newer):

npm install -g @moonshot-ai/kimi-code

Open a new terminal and check it:

kimi --version

Log in

kimi login

This starts a device-code login in your browser. You can also start kimi and type /login inside it.

Don't show your screen or share the output of kimi login or kimi web: they can print codes or tokens for your account.

Select K3.1 Pro

Start Kimi in your project folder and pick the model:

cd <PROJECT>
kimi
/model

Choose K3.1 Pro. There is also K3.1 Pro Highspeed: it's faster, but it costs 2× the usage of your plan. I used the normal K3.1 Pro for the whole build. Which models you see depends on your Kimi plan. If a new model is missing, run /logout and /login again.

3 · The mcp.json file

Kimi Code reads its MCP servers from %USERPROFILE%\.kimi-code\mcp.json (all projects). A .kimi-code\mcp.json inside a project folder applies only to that project. Here is my full file with placeholder paths. Each part is explained below.

{
  "mcpServers": {
    "comfyui": {
      "command": "C:\\Program Files\\nodejs\\node.exe",
      "args": [
        "C:\\Program Files\\nodejs\\node_modules\\npm\\bin\\npx-cli.js",
        "-y",
        "comfyui-mcp"
      ],
      "env": {
        "COMFYUI_HOST": "127.0.0.1",
        "COMFYUI_PORT": "8188",
        "COMFYUI_PATH": "C:\\path\\to\\ComfyUI-Easy-Install\\ComfyUI"
      }
    },
    "blender": {
      "command": "uvx",
      "args": ["blender-mcp"]
    },
    "godot": {
      "command": "C:\\Program Files\\nodejs\\node.exe",
      "args": [
        "C:\\Program Files\\nodejs\\node_modules\\npm\\bin\\npx-cli.js",
        "-y",
        "@coding-solo/godot-mcp"
      ],
      "env": {
        "GODOT_PATH": "C:\\path\\to\\Godot_v4.7-stable_win64_console.exe"
      }
    }
  }
}
Why node.exe plus npx-cli.js? On Windows, npx is a .cmd script, and some programs can't start it directly. Calling Node with npm's npx-cli.js runs the same npx -y … command and works everywhere. The paths above are the default Node.js install location; change them if you installed Node somewhere else. In JSON, every backslash is written twice.

4 · ComfyUI MCP

Server: comfyui-mcp, started with npx -y comfyui-mcp (needs Node.js 22+).

VariableWhat it is
COMFYUI_HOSTThe address ComfyUI listens on. 127.0.0.1 for the same PC.
COMFYUI_PORTThe port ComfyUI runs on. If you leave it out, the server tries 8188 and then 8000.
COMFYUI_PATHYour ComfyUI folder (the one with models, input, output and user), so Kimi can find models, workflows and results.

Start ComfyUI on that port

ComfyUI's default port is 8188, so with the file above you just start ComfyUI as usual. To use another port (I used 8189, because another app already had 8188), add --port to the start command and put the same number into COMFYUI_PORT:

.\python_embeded\python.exe -I ComfyUI\main.py --windows-standalone-build --port 8189

In ComfyUI-Easy-Install, add the extra arguments in the start .bat at the end of the python.exe … main.py line, or with the "Startup arguments" option of its menu. Then open http://127.0.0.1:8189 in your browser to check that it runs.

5 · Blender MCP

Server: ahujasid/blender-mcp. It has two parts: an add-on inside Blender, and the MCP server that Kimi starts with uvx.

The project has been renamed to MCP for Blender (PyPI package mcp-for-blender). According to its README, uvx blender-mcp still works, and that's what my config uses. For a new setup you can also write "args": ["mcp-for-blender"].

a) Install uv

uvx comes with uv. In PowerShell:

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

or with winget:

winget install --id=astral-sh.uv -e

Open a new terminal and check it with uvx --version.

b) Install and enable the add-on

  1. Download addon.py from the repo (on GitHub: Download raw file).
  2. In Blender: Edit → Preferences → Add-ons → Install… (in Blender 4.2 and newer it's in the ▾ menu at the top right of the Add-ons page: Install from Disk…) and choose addon.py.
  3. Tick the box next to Interface: MCP for Blender.

c) Start its server inside Blender

  1. In the 3D Viewport, press N to open the sidebar.
  2. Open the MCP for Blender tab.
  3. Click Connect to MCP server. It should show that it's connected on port 9876. Newer versions of the add-on start this automatically when Blender opens.

Keep Blender open while Kimi works. Only one MCP client should talk to Blender at a time: close other AI apps that use the same add-on.

6 · Godot MCP

Server: Coding-Solo/godot-mcp, started with npx -y @coding-solo/godot-mcp.

  • Set GODOT_PATH to the console exe of Godot 4.x, for example Godot_v4.7-stable_win64_console.exe. The console version prints Godot's output to the terminal, so Kimi can read errors.
  • It lets Kimi launch the editor, run the project, read the debug output, and create or edit scenes.
  • It can't take screenshots. In my prompts, Kimi adds a small debug script to the game that saves screenshots with get_viewport().get_texture().get_image().save_png().

7 · Check that it works

  1. Start ComfyUI, and Blender with the add-on server running.
  2. Run kimi doctor. It checks Kimi's own config files (config.toml and tui.toml). It doesn't check mcp.json; that's what the next step is for. 
    kimi doctor
  3. Start kimi in your project folder and type: 
    /mcp
    It shows the connection status of every server. comfyui, blender and godot should all be connected.
  4. A quick test prompt: "Use the ComfyUI MCP to show the system stats, list the objects in the open Blender scene, and tell me the Godot version."

8 · Troubleshooting

  • ComfyUI doesn't connect: the port in COMFYUI_PORT must match the port ComfyUI runs on. Open http://127.0.0.1:<port> in the browser. If nothing loads, ComfyUI isn't running on that port.
  • Blender doesn't connect: the add-on's server isn't started. Press N → MCP for Blender → Connect to MCP server, then check /mcp again. Also check that uvx works in a new terminal.
  • Godot doesn't connect: GODOT_PATH must point to the exe file itself, not to the folder or the zip. Use double backslashes in JSON.
  • ComfyUI jobs fail with disk or temp errors: my C: drive was full (48 MB free), and the mesh nodes couldn't write their temp files. Free up space, or move ComfyUI's temp folder to another drive. Add this to the start command: 
    --temp-directory D:\ComfyTemp
    Some nodes also use Windows' own temp folder. Setting it in the start .bat, before the python.exe line, moves that too: 
    set TEMP=D:\ComfyTemp
set TMP=D:\ComfyTemp
    Don't let Kimi patch the custom nodes' code to fix this. That's what it tried first.
  • Asking Kimi to fix a connection: name the exact error and the server. When I wrote "fix the broken MCP connection", Kimi worked on Blender, the one server that was working, and broke it. With the error message pasted in and the server named, it fixed mcp.json in minutes.
